# Claude Code CLI acceptance, 2026-10-26

All three opt-in tests passed against `http://127.0.0.1:4000` with real Claude Code CLI coding tasks. Each copied an initially failing fixture, used native Read, Edit, and PowerShell tools, changed only its permitted source files, and passed its fixture tests after coding. Each CLI call ended with a successful terminal result, with no reported API retries. The launcher revoked each temporary inference key and checked that its alias was absent from `/key/list`.

The unknown-name case also sent a direct native Anthropic Messages request before the CLI task. Its response was HTTP 200 with a terminal `end_turn`, the requested marker, and the caller's unknown model name preserved. The `x-litellm-model-id` response header matched a deployment for the saved default. At that preflight the saved default was `minimax-flash-direct` in `off` mode. The test did not change routing policy. The other two cases' saved policy was not recorded in their receipts, so their success proves CLI acceptance of the requested names, not a particular internal deployment.

The current harness keeps Claude's copied workspace separate from redacted audit logs and its isolated config. It disables unsupported `[1m]` model aliases, pins the CLI's model-card environment overrides to the requested name, bounds thinking, and sends a 60-second LiteLLM stream-timeout header. It provisions one 20-minute, $5-budget virtual inference key per case, runs one test process at a time, and revokes each key in `finally`. A case fails on incomplete CLI termination, API error, fewer than 20 completed turns, less than 180 seconds, missing native tool use/results, changes outside permitted source files, or failing fixture tests. CLI calls are bounded at 450 seconds and 150 seconds of output idleness; a whole case is bounded at 900 seconds.

Earlier attempts were useful failure receipts, not acceptance passes. A $0.50 key budget caused an HTTP 422 preadmission failure, and a two-request parallel cap caused HTTP 429s; the launcher now uses the budget and concurrency settings above. A trial 4096-output-token cap caused a Claude CLI API error during a long coding review, so that cap was removed. The original appointment scheduling fixture repeatedly led the model into exhaustive time-zone scans and timed-out reviews; the finite build-planner fixture replaced it. Moving audit logs outside the copied workspace also stopped Claude from reading its prior run artifacts during a fresh review call. Earlier unknown-name attempts ended without a terminal CLI result while `requesting`; the final unknown-name run completed under the current isolated harness. These observations do not by themselves identify a gateway source defect, and no gateway runtime code was changed.

The successful runs still included recoverable tool errors, counted from the redacted CLI JSONL. In each case the model tried `Write` even though that tool was disabled; Claude returned an explicit tool error and the model recovered. Other errors were failed task commands or edits. In the billing case, Claude's path guard blocked a `Remove-Item _t.py` cleanup command following a temporary script check. No unexpected files remained in the workspace. The harness now records tool error and unavailable-tool counts in future receipts, and requires at least one non-error tool result.

`python -m py_compile` passed for the two harness modules. Without the live opt-in flag, pytest reported three skipped tests. The three live receipts above are the acceptance evidence. They sample three requested names and configurations; they do not prove every possible model card, every saved-default target, or production deployment behavior.

A final fresh live fallback probe also passed with `minimax-flash-direct` in `off` mode. During the completion audit, the current worktree's routing source had changed to pass requested names through unchanged in `off` mode. Source/runtime parity for that concurrent change is unverified. The passing receipts describe the running endpoint; the unknown-name acceptance preflight will fail if a later rollout no longer resolves unknown names to the saved default.
