# Local Qwen: domain tasks and Sift compaction

Date: 2026-10-15. Model: Unsloth Qwen3.8-27B `UD-IQ3_S` GGUF through the local llama.cpp server and the Subroute staging gateway. The gateway offers the public alias `qwen3.8-27b`; the server has a 32,768-token context and the gateway compacts oversized histories to at most 24,576 estimated input tokens. Staging's saved routing and Advisor policy was restored after each run.

## Claude Code acceptance

Each task was a fresh, isolated fixture with a failing baseline, two source modules, visible tests, and separate held-out tests. Native Claude Code used Read, Edit, and PowerShell against the staging Anthropic Messages route. Its prompt required tests before and after edits. The harness checked that visible tests were unchanged, then ran them and the held-out tests independently. A task counts as fully accepted only when Claude Code exits successfully, edited source, performed the test loop, and passed both test sets. The timing sample is this local hardware and these three runs, not a population estimate.

A later `context_compaction` fixture run delayed Claude Code's own auto-compaction setting to 95% and allowed 900 seconds and 32 turns. Claude Code finished in 591.89 seconds with a real failing-before, passing-after PowerShell test loop and a successful terminal result. Mean first-token time was 2.10 seconds; llama.cpp generation was 43.75 tok/s over 28 completions. The six visible tests passed. Three independent holdout cases were added after the run and executed against its frozen workspace; all three failed. The implementation forwarded 141 estimated tokens under a 100-token target, failed to reject a system-plus-active span that could not fit, and rewrote old assistant media as text. The llama.cpp slot reached 21,624 tokens, then dropped to 8,487 when the Claude client compacted its own session. No gateway Sift compaction event was observed in this run. This does not test whether Sift would have activated on a native Claude request over the 24,576-token gateway target.

LiteLLM 1.103.0's tool-schema counter indexes `items` for every array and raises `KeyError('items')` when a client tool schema omits it. Its normal pre-call check logs the error and skips that count. The local Sift hook now retries counting with `items: {"type": "string"}` added only to a bounded copy of the tool schema. The original request is not rewritten. A focused test reproduces the real LiteLLM exception and verifies original-tool identity and budget compliance. After both gateways restarted, a staging Chat Completions request with a 202,878-character prior log and a tool array without `items` returned `cobalt`, HTTP 200, `stop`, and 2,253 provider-reported input tokens in 4.63 seconds. LiteLLM still logs its separate pre-call counting error; the Sift hook provides its own bounded estimate before forwarding. Remove this workaround when the deployed LiteLLM counter handles this schema.

## Context compaction

The previous local compactor preserved the active turn and recent complete turns but selected older evidence only from the head and tail. Sift replaces that older-evidence selection with bounded query-aware excerpts. The failure mechanism addressed is loss of a needed fact buried in a long log. It preserves message-level instructions, the active user/tool chain, the 1M estimated-token intake ceiling, 24,576-token forwarding target, and no additional model call. A vendored library adds an algorithm and synchronization obligation; `src/sift/UPSTREAM.md` records its source and update gate.

Standalone Sift tests: 13 passed. Its authored seeded middle-fact benchmark: 100/100 retained versus 0/100 for an 800-character head/tail baseline. This benchmark deliberately favors middle retrieval and does not establish general recall or answer quality. A live staging trace of 202,878 characters placed `DEPLOY_KEY_73 = cobalt` at its midpoint. Anthropic Messages returned `cobalt`, HTTP 200, `end_turn`, 2,014 input tokens in 4.62 seconds. Chat Completions returned `cobalt`, HTTP 200, `stop`, 2,014 input tokens in 1.62 seconds. Both used a 512-token output cap. These responses establish live protocol integration and retrieval for this case. The second request may have benefited from the first request's prefix cache; the timings are not a controlled latency comparison.

A separate 90,000-line, 3,138,877-character Anthropic trace also buried the key in its midpoint. The staging request returned `cobalt`, HTTP 200 and `end_turn` in 4.88 seconds, forwarding 2,107 input tokens. This tests multi-megabyte CPU intake in the live gateway. The raw token estimate was not exposed in the response, so this result does not prove a full one-million-token request was processed.

The existing Anthropic regression probe sent 585,011 characters, including an in-sequence system entry that the Qwen template needs moved to the instruction prefix. With Sift loaded, it returned `PONG`, HTTP 200, and 338 forwarded input tokens in 2.03 seconds. The short response checks translation and compaction behavior, not historical recall.

Subroute's focused configuration and compaction tests passed 22/22; the full suite passed 730, skipped 39. The normal pytest run excludes `tests/acceptance` because those deliberately failing fixtures and held-out modules run only in the isolated harness.

Sift `v0.1.0` was pushed to `https://github.com/stancsz/sift` at commit `f94acf1`. Its GitHub Actions test runs for the commit completed successfully. Production and staging gateways restarted with the vendored Sift import, returned HTTP 200 readiness, and retained their saved force-route and Advisor selections.

## Long tool loops under one user request

The first Sift revision treated the entire span since the last non-tool user message as immutable. Claude Code's three recorded task traces each contain 18 or more tool cycles under one original request. At a forced 5,000-token budget, that rule would reject compaction even when the task prompt and newest tool cycle fit. The revised boundary preserves those two items, keeps up to three additional recent cycles when affordable, and turns older cycles into quoted historical excerpts. It also omits old Anthropic thinking blocks from extracted evidence while preserving current thinking blocks unchanged.

A private replay of five local Claude Code traces used a deterministic 4-character token estimate. The traces covered streaming, billing, scheduling, context planning, and policy persistence, with 23 to 66 messages and raw estimates of 7,906 to 15,869 tokens. At a forced 5,000-token target, all five preserved the original request and latest tool message within budget. A retrospective query about a labeled initial test failure retained the matching failure line in 5/5 traces. A naive 20,000-character head/tail string slice retained that same line in 2/5. This slice is a span-retention reference, not a protocol-preserving gateway baseline. The raw CLI logs stay local; the replay script prints only aggregate results. These are selected queries from five generated task traces, not a held-out population estimate. Their original raw sizes were below the actual 24,576-token runtime target, so the 5K replay tests a boundary rather than claiming those CLI runs activated production compaction.

A staging Anthropic request with 36 synthetic tool cycles and 348,116 characters of message content returned HTTP 200, `end_turn`, and the exact newest failure name `test_sift_cycle_35` in 15.19 seconds. Its provider-reported input was 18,434 tokens. Staging policy was restored. Two earlier probes with a longer repetitive tool pattern returned a tool call or tool-shaped text instead of the requested answer; the final probe marks its last tool result as terminal. This result confirms one live long-loop answer, not reliability across arbitrary agent histories.

An equivalent 36-cycle Chat Completions request returned HTTP 200, `stop`, and `test_sift_openai_35` in 16.41 seconds with 18,334 reported prompt tokens. Staging policy was restored again. Together these probes cover both public protocol surfaces for this specific long-loop pattern.

For an answer-quality check, six actual failed-test outputs were taken from the local Claude Code task logs, placed between 4,500 routine lines on each side, and queried through staging Chat Completions. Five queries asked whether a named test was marked `ERROR`; one follow-up asked about a named `FAIL` in a later run. Qwen answered all six correctly with normal `stop` outcomes. Each raw request contained about 415K to 417K characters, while provider-reported input was 2,199 to 2,351 tokens after compaction; response times were 2.42 to 4.31 seconds. These are selected binary questions with artificial padding, not a blinded measure of general task performance. The six-case script keeps the raw test logs local and restores staging policy.

The correction is published as [Sift v0.2.0](https://github.com/stancsz/sift/tree/v0.2.0) at commit `a12d211`. The public package includes the reproducible synthetic and protocol tests; the raw Claude Code traces remain local.

Both GitHub Actions runs for `a12d211` completed successfully. Subroute's production and staging gateways restarted with the identical vendored core, returned HTTP 200 readiness, and retained force routing. This confirms deployment and health, not broad model-answer reliability.

## Adjacent diagnostic loss and Sift 0.3.0

A new native Claude Code `context_compaction` run used a 1,000,000-token client context setting and a 95% client auto-compaction threshold. It finished in 250.97 seconds with a failing-before, passing-after six-test loop, mean first-token time 1.21 seconds, and 44.10 generated tokens/s across 18 server completions. Its post-run holdout still failed. The replayable trace estimated 19,790 tokens and the llama.cpp slot reached 20,119, both below Sift's 24,576-token trigger. This run therefore does not attribute the holdout failure to Sift.

A separate matched synthetic regression demonstrates an actual Sift loss. A 1,000-line log placed `FAILED test_invoice_total` immediately before `rounding_mode=HALF_EVEN; observed +0.01 versus Decimal expected`. At a 700-token target, Sift 0.2.0 kept the failure name but omitted the adjacent diagnostic; Sift 0.3.0 kept both under the same target. A live staging Chat Completions request with 6,000 lines on 0.2.0 returned HTTP 200 and said the cause was absent from its evidence. The matching request on 0.3.0 forwarded the diagnostic and included `HALF_EVEN` in its response. With a clearer question asking for the setting immediately after the failure, 0.3.0 answered exactly `rounding_mode=HALF_EVEN` through both Chat Completions (`stop`) and Anthropic Messages (`end_turn`), each with 22,570 provider-reported input tokens. Staging policy was restored after every probe. The two versions used the same history and budget for the first live comparison; the final exact-answer prompt was only tested on 0.3.0. The 0.2.0 and 0.3.0 matching first responses took 11.56 and 20.2 seconds, with 2,004 versus 22,568 reported input tokens. Two later 0.3.0 requests took 2.58 and 4.05 seconds after prefix reuse. These times show a plausible cold-prefill cost of retaining more context, not a controlled latency estimate.

Sift 0.3.0 keeps the immediate neighbors of each selected source piece and removes the fixed 96-excerpt ceiling, while retaining the caller's hard token budget and a 512-candidate bound. This spends more prompt space to preserve local explanation. The standalone suite passed 17 tests, the seeded middle-fact benchmark remained 100/100, five private Claude trace replays kept the task, latest tool message, and queried initial failure in 5/5, and Subroute's focused local-context suite passed 13 tests. The full Subroute suite passed 732 tests with 39 skipped. A 90,000-distinct-line authored case estimated 784,764 raw tokens, forwarded 16,420, retained the paired diagnostic, and completed the CPU compaction in 0.68 seconds on this desktop. These samples show a repaired failure mechanism, not a general agent completion improvement. The source is published as [Sift v0.3.0](https://github.com/stancsz/sift/tree/v0.3.0) at `8e8c293`; both GitHub Actions test runs succeeded, and the vendored core has the same SHA-256 as that source. Production and staging gateways restarted with HTTP 200 readiness and their saved routing and Advisor policies unchanged.

## Native LiteLLM callback and cache-aware Sift 0.4.0

Sift 0.4.0 moves the Qwen compaction policy into an optional native LiteLLM Proxy callback, registered after Subroute's routing callback. The dynamic router retains only the existing Claude system-message frontload needed by the local Qwen template. LiteLLM continues to own public protocol handling and provider transport. Sift calls the deployed LiteLLM 1.103.0 route counter, uses a bounded counting-only tool-schema repair for that version's missing-array-`items` bug, and adds `x-sift-*` estimate headers. The maintenance cost is a version-specific callback and a vendored package copy. The callback's private counter call should be reevaluated when LiteLLM changes version. The local development lock remains on LiteLLM 1.101.0 because upgrading the proxy extra to 1.103.0 conflicts with the repository's MCP 1.x music extra; the actual 1.103.0 container ran the six callback tests and live probes.

Completed four-cycle tool groups now use fixed task-anchored excerpts; an unfinished group can still change. In five private trace replays at a forced 5K target, median serialized prompt-prefix overlap between tool-result turns changed from 0.085/0.085/0.033/0.060/0.069 on 0.3.0 to 0.241/0.209/0.363/0.195/0.075 on 0.4.0. All five labeled baseline failures remained present in later-query trials. On a 65,368-estimated-token billing stress trace, all four named incident codes remained present within 20,515 forwarded estimated tokens; 0.3.0 used 24,411 and also kept all four. Its median serialized prefix overlap rose from 0.007 to 0.749 across 18 tool-result transitions. These comparisons are CPU-side prompt text metrics, not model cache hits or answer-quality gains.

The native billing stress Claude Code run read all four audit dossiers, made 25 model completions over 759.57 seconds, and reported 19.15-second mean first-token time and 40.01 generated tokens/s. It performed no source edits and failed both visible and held-out tests, despite its CLI terminal subtype reporting success. The oversized repetitive dossiers made the task a poor code-solving acceptance fixture, and its failure is recorded rather than counted as an accepted run. Its live prompts showed about 12% to 16% prefix reuse before the 0.4.0 grouping change.

With the native callback on staging, the 6,000-line adjacent-diagnostic probe answered `rounding_mode=HALF_EVEN` through Anthropic Messages and Chat Completions with HTTP 200 and `x-sift-compacted: true`. The revised 36-cycle live probes returned the newest failing test through both protocols with 26,400 and 26,450 provider-reported input tokens. Those counts exceed Sift's 24,576 LiteLLM estimate but stay below the model's 28,672 configured input cap; 4,096 output tokens still fit the 32,768 context window. Two adjacent live 34- and 35-cycle requests shared about 62% of their rendered prompt text but llama.cpp reported only 57 cached tokens each, with roughly 24K tokens reprocessed per call. A direct simple 26K-token server request reused over 25K tokens when only its last line changed. The Sift change therefore has not delivered a measured first-token speedup on this tool-loop shape. Sift 0.4.0 was published at [commit f89a412](https://github.com/stancsz/sift/commit/f89a412); its local suite passed 24 tests and Subroute's full suite passed 722 with 39 skipped.

## Fixed-boundary Sift 0.5.0 cache result

The 0.4.0 replay improved serialized prefix overlap but a live tool-loop pair still reused only 57 tokens. Sift 0.5.0 keeps completed four-cycle excerpts fixed and appends the current group's exact tool messages behind them while that group fits a reserved third of the 24,576-token input target. At the next group boundary it recomputes the historical excerpt. When a group is too large, it falls back to the existing bounded selection and can lose cache reuse. This changes the compaction algorithm without adding a service, store, provider call, or transport path.

In a staging 34/35/36-cycle sequence, all three Chat Completions responses named the newest failing test with HTTP 200. Gateway forwarded estimates were 18,959/20,948/22,937 tokens; provider-reported prompt tokens were 20,769/23,049/25,329. llama.cpp reported 0/20,765/23,045 cached prompt tokens, and buffered response times were 17.22/4.15/3.86 seconds. The exact current group gave the server an append-only prompt within that boundary. On the 37th cycle, the fixed group rolled over: cached tokens fell to 57 and that response took 13.93 seconds while still naming the newest failure. The reproducible `tests/acceptance/qwen_claude/probe_sift_cache_reuse.py` passed its cache and answer gate on a repeat run. Fresh 36-cycle Anthropic Messages and Chat Completions probes returned the newest failure with normal terminal outcomes and 26,400/26,450 provider-reported input tokens. The 6,000-line paired-diagnostic question still returned `rounding_mode=HALF_EVEN` through both protocols.

At a forced 5K target, private replays of five native Claude Code traces retained the original task, latest tool message, and labeled initial failure in 5/5 later-query trials. Median serialized prefix overlap between tool-result turns was 1.0/1.0/1.0/0.653/0.542, up from 0.4.0's 0.241/0.209/0.363/0.195/0.075. A 65,368-estimated-token billing stress replay kept all four named incident codes within 20,515 forwarded estimated tokens. The standalone Sift suite passed 25 tests and its seeded middle-fact benchmark remained 100/100; Subroute's full suite passed 722 with 39 skipped. This is a selected cache and span-retention check; native Claude Code completion of a long coding task was not remeasured on 0.5.0, and an epoch rollover may still cause a cold prefill. The source is published as [Sift v0.5.0](https://github.com/stancsz/sift/tree/v0.5.0) at `10142e8`, with both GitHub Actions runs successful.
