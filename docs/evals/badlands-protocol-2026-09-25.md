## Scope and observed behavior

The active target is the Codex-backed local path used by Badlands at `127.0.0.1:4000`, preserving Chat Completions, Responses, and Anthropic Messages request and streaming contracts.

- Running production logs contain Codex `/v1/messages` 400 errors with `Stream must be set to true` from the Codex Responses endpoint.
- Running production and staging containers use LiteLLM 1.103.0. The repository's optional Windows environment uses Python 3.13.11 and LiteLLM 1.101.0, as recorded in the earlier runtime evaluation. Treat these as distinct runtimes.
- LiteLLM 1.101.0's native Chat-to-Responses bridge does not force upstream streaming for a non-streaming caller. Its Anthropic Messages adapter requires a complete Responses object when the caller requested non-streaming.
- LiteLLM's native `chatgpt` provider forces stream mode and has an SSE-to-completed-Responses parser. Its built-in authenticator expects a different auth-file shape than Subroute's `{ "tokens": { "access_token", "account_id" } }` layout. Whether Subroute can safely adapt the credentials for that native provider remains unverified.
- Direct source inspection and an isolated transform fixture for the native `chatgpt` provider showed it appends default Codex instructions and rebuilds the body from an allowlist. This can change caller instructions or omit parameters such as token limits. It is not accepted as a drop-in fix.
- LiteLLM 1.101.0's standard Responses-to-Chat transformer maps string input to a user message and converts roleless `function_call` and `function_call_output` items into assistant tool calls and tool messages. A public `litellm.aresponses` SDK fixture asserts those messages reach the registered custom adapter intact. This corrects the earlier audit claim that roleless tool items were dropped.

## Custom provider adapter evaluation

`src/subroute/handlers/codex_subscription.py` is a narrow LiteLLM `CustomLLM` adapter. It forces only the Codex upstream call to stream, assembles non-streaming Chat responses with LiteLLM's `stream_chunk_builder`, validates a terminal finish reason, preserves provider usage when supplied, and closes the upstream iterator on completion or cancellation. Streaming Chat chunks are mapped to LiteLLM's generic custom-provider chunk contract, then LiteLLM builds the public protocol streams. The five Codex deployments explicitly allow `reasoning_effort`, which LiteLLM otherwise rejects for this custom provider. It does not implement public Chat, Responses, or Messages protocols itself.

When the Codex stream contains no provider usage, the adapter clears LiteLLM's locally estimated usage instead of presenting it as provider-reported usage. A focused regression fixture covers that case.

The Codex adapter implements LiteLLM's `GenericStreamingChunk` contract. It converts upstream Chat stream chunks, tool calls, terminal reasons, and provider usage into that generic form, which LiteLLM then translates into public protocol events. Direct Chat chunk passthrough was invalid for `CustomLLM.astreaming`; the public Responses streaming fixture exposed and verified this correction.

## Antigravity authentication and process-boundary decision

The repository's direct `agy` fallback in `src/subroute/handlers/antigravity.py` is a child process, and Compose currently selects the HTTP sidecar path for both gateway instances. The sidecar also owns onboarding initialization and three persistent volumes containing active OAuth/config/cache state. Thus production and staging currently share Antigravity credential/config/cache state despite their separate policy and database storage. A service-only move into the gateway image would remove the Compose service but still launch the CLI as a child. The public SDK does not document an in-process API for the personal CLI subscription, and the user explicitly disallowed Gemini API-key auth while approving the other available process boundary. The GOAL now records the Compose sidecar as an explicit exception that preserves the subscription. The shared-volume behavior remains documented and is not claimed as isolated.
