# Relay pilot evidence, 2026-10-23

Original intent: a Docker-preferred LAN MCP gadget that lets a Claude Code orchestrator coordinate sessions across devices, keep bounded work aligned with goals through Northstar, and optionally consult Advisor about the next action.

Delivered scope: independent coordinator, machine polling API, durable SQLite workboard, local runners, bounded headless supervision, optional explicit Advisor tool, isolated coordinator and worker Compose files, hash-locked Python dependencies, a version-pinned Claude Code client image, examples and [device A/B setup](../operations/relay-devices.md). No gateway provider callback, public inference protocol, production/staging policy or global client setting was changed for Relay. Other edits already in this shared checkout remain outside this delivery. The owner explicitly chose same-device Docker testing first; physical-device and sustained criteria remain visible for the next stage.

## Skill learning

At this revision, the installed Starlette Host middleware and its legacy HTTPX test transport split IPv6 authorities incorrectly. Relay uses the official MCP SDK's maintained Host validation for both MCP and machine endpoints; a Host-header regression covers bracketed IPv6. The test injects the real header over the in-process transport, rather than claiming a real IPv6 socket check.

The first Docker build exposed a Windows-only `pywin32` entry in a host-specific dependency lock. Recompile this standalone service with `uv pip compile --universal --generate-hashes`; the final Linux build preserves Windows markers and skips that package correctly. The installed npm Claude package points at a native `bin/claude.exe`, so read its `package.json` bin entry instead of assuming `cli.js` or invoking an `.exe` through Node. These are scoped portability lessons, not reasons to add another dependency or modify gateway routing.

Native Claude `--tools` takes built-in tool names; `--allowedTools` carries patterns such as `Bash(python*)`. These must remain separate for actual test execution. The first implementation did not distinguish them; the repaired adapter does. Work awaiting review now reserves its node/workspace until acceptance or explicit cancellation, allowing only its matching review so a different writer cannot change the artifact under acceptance.

The Northstar package's current `default` worker alias follows the saved target. A remembered model-pinning preference must be reconciled with later explicit owner corrections before treating it as a blocker. Retrieving the original routing conversation resolved this task's false blocker without changing global policy. No global memory/installed skill was edited or public issue posted.
