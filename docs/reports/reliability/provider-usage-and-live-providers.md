## 2026-09-29 advisor failure classification repair

The live oversized-advisor request had been fail-closed but surfaced as HTTP 500 because `AdvisorPlugin` replaced typed provider failures with a generic `RuntimeError`. It now preserves a useful bounded gateway status while leaving LiteLLM responsible for the public protocol: invalid translated input 400, the local bridge payload limit 413, upstream quota/capacity 429, timeout 504, and upstream auth/connectivity/server errors 502. Error logs retain request/consultation correlation and a capped redacted cause; the client receives correlation IDs and the fail-closed message, not the provider body. Codex upstream statuses are represented by a typed adapter error, and HTTPX timeout exceptions are no longer flattened into connection failures.

The deployed LiteLLM 1.103.0 staging `/v1/messages` hook path was exercised with an oversized request that fails before bridge/provider dispatch. It returned HTTP 413 with Anthropic's `type: error` envelope; a following real Gemini Subscription target call succeeded. Before the final Gemini target-timeout mapping, the active-provider failure matrix passed 9 tests in 67.26 seconds. Focused advisor/Codex/Gemini tests passed 111; the locked full suite passed 246, with 9 live-only skips and 28 warnings. The live fixture restored staging policy; production policy remained unchanged during staging verification.

The external-provider auth/quota/outage/timeout paths were classified with local HTTPX transport fixtures, not by injecting real failures into live accounts. They remain an explicit evidence boundary in [GOAL.md](../../../GOAL.md), not a claim of live fault coverage. Sol consultation receipt: `codex-sol-advisor`, request `chatcmpl-codex-advisor-f3cf50f438e4`, 465 prompt / 550 completion tokens, 16.291 seconds; the staging protocol check confirmed the action and `decision_changed: false`.

Final-source live verification confirmed an actual transient Gemini Subscription 3.6 Flash provider `INTERNAL 500`: sidecar status `ERROR`, public target response HTTP 502, no hidden retry/fallback. A deliberate next request to the same model returned HTTP 200 with the exact recovery marker and provider usage; the remaining-alias subset then passed 1/1. Production was recreated to load final source without policy changes and passed a real Codex Subscription Messages marker request (20/14 provider tokens).
